# 06 踩坑清单（两部片子真实踩过的）

1. **钩子一看就知道 = 没用；钩子说不通 = 翻车。** 每句旁白都问两个问题：观众想不到吗？AI 说出来成立吗？（见 剧本模板.md）
2. **说「上一部」之前先查上一部。** 《溢出》写了「上一部的纪录，十的六十四次方」，实际上一部算到了 10³⁰⁸。改旁白、重配音、高潮重做，比发出去被评论区指出来便宜得多。
3. **视频模型把内存吃光。**
   - 本地 H3 约要 35 GB 提交内存，32 GB 内存的电脑要把虚拟内存设大。
   - 服务要开在用户自己的窗口里，别让 AI 在后台开：内存一紧，后台进程会被系统收掉。
4. **截图工具泄漏进程。** 每次出缩略图都起一个预览服务器，只杀父进程会漏掉子进程，一次攒了 124 个、吃掉 14 GB。关服务要杀整棵进程树（Windows：`taskkill /T /F`）。
5. **只让一个分身碰显卡。** 多个分身同时提交任务，队列会乱，也会一起把内存挤爆。
6. **时间不要写死在场景里。** 全部从同步点推，改剪辑时场景自己跟着走。
   - 《溢出》里还是有两处写死了：仪表发烫的时间段、火花推近的起点。
   - 要剪掉 12 秒时差点出问题，最后用「旧时间轴 + 剪点」的办法绕开了（见 交付规格.md）。
7. **转场前先定写实镜头。** 首尾帧转场的最后一帧就是写实镜头的第一帧；换一条写实镜头，关键帧和转场都得重做。
8. **不写变化过程，转场就会「一刷而过」。** 提示词里写清楚怎么变、变多久（见 docs/08_视频模型.md）。
9. **升级 2K 要逐条对比，别整批替换。** 贵的不一定更好：本地版的闪电劈地、火山喷发更猛，就留了本地版。
10. **声音跟着画面走。**
    - 快闪、跳档、心跳，每个画面事件都要有声音，每个声音都要有画面。
    - 让画面分身报出每个事件的精确时间，转给声音分身。
11. **响度按平台来。** −14 在抖音偏小，−12 刚好；推响度靠限幅器，不要用归一化。
12. **水印别太粗。** 小字号的粗体在压缩后糊成一团（见 交付规格.md）。
13. **小字放在花背景上要垫底色。** 封面上的「片名 / TITLE」一开始完全看不清。
14. **署名跟着改。** 烟花换成 API 出的之后，片尾「本地显卡生成」就不成立了，要改成「本地显卡 + 官方 API 生成」。
15. **进度要能远程看。** 每 10 分钟往飞书发一条简报，写清在做什么、还要多久。用户不在电脑前也知道进度，也能随时插话改需求。
