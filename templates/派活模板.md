# 03 派活模板（导演 → 分身）

> 这些是《溢出》里导演给分身派活的真实写法，整理成模板。原则：
> - 一次说清目标、时间点、约束和交付物。
> - 给数字不给形容词。
> - 要求截图汇报。
> - 写明「不许碰」的东西。

## 1 画面分身（开工）

```
你是《〈片名〉》的〈段落〉分身，负责 〈起〉–〈止〉 s。先读 PRODUCTION.md 和剧本第 〈N〉 幕。
要做的：
1. 〈画面节拍 1：时间点（从 cues.json 的 〈cue 名〉 读）+ 画面 + 声音会落在哪〉
2. 〈画面节拍 2〉
约束：
- 只改 〈文件〉；时间全部从 cues / lyrics 推，不写死。
- 只出静帧 / 缩略图，一次只开一个 Chrome，不碰 GPU 和生成服务。
- 屏幕上的每个字必须字面属实。
交付：一张 〈起〉–〈止〉 的缩略图 + 关键时刻的全尺寸静帧；给配乐分身列出所有画面事件的精确时间。
```

## 2 生成镜头分身（E，唯一碰 GPU 的）

```
你负责全部写实镜头。服务由用户开在自己窗口里：永远不要启动、重启或关闭它；它崩了就记日志、告诉我、等。
队列：queue.txt 一行一条，runner 一次只跑一条。
每条出来后：
- 看 6 帧拼图，对照 shots.md 里这条镜头的目的判断。
- 采用：复制到 clips_src/<id>.mp4，并运行 clips.py <id>。
- 不采用：追加一次重抽，换种子并改提示词；只在明显不能用时才重抽，一条约 4.5 分钟。
首尾帧转场：检查第 0 帧和关键帧、最后一帧和写实镜头第 0 帧的接缝（PSNR / SSIM），每条采用后立刻告诉我。
```

## 3 声音分身（F）

```
〈新需求一句话，引用用户原话〉。新的同步点：〈cue 名 = 时间列表〉。
要的声音：
- 〈事件〉：〈时间〉，〈性质：短 / 硬切 / 无混响 / 在人声下面〉
- 人声永远在最上面，任何一句都要高出底 7 dB 以上
规矩：
- 〈窗口〉 以外保持和上一版逐采样一致
- 全片 −12 LUFS，AAC 编码后 ≤ −1.0 dBTP
汇报：改了哪些文件、各段响度表、限幅器最大压缩量在哪、让我重点听的地方。
```

## 4 改片（用户提意见之后）

```
用户看完第 〈N〉 版，原话：「〈原话〉」。
我的理解：〈要改的点，具体到时间和数值〉。
已经改好的数据：〈cues / lyrics 的变化，旧 → 新〉。
你要做：〈具体改动〉。
不要动：〈其他段落〉。
交付：〈缩略图时间范围〉 + 〈关键静帧〉。
```

## 5 并行调度的几条经验

- **按依赖排：** 能并行的同时开（画面、声音、生成镜头），有依赖的写清「等 X 交了再做」。
- **导演自己做的：**
  - 同步点和时间轴（全片只有一份）。
  - 最终渲染和编码。
  - 事实核对：屏幕上的每个数字都回到文件里查。
- **进度：** 维护一个 STATUS.json。`brief_loop.py` 读它，每 10 分钟往飞书发一条简报，用户不用盯着终端。
- **分身互相需要的信息由导演转达：** 例如画面事件的时间转给声音分身，写实镜头的接缝报告转给跨界分身。
