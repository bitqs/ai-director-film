# 08 写实镜头：视频模型

《溢出》的写实镜头（焊花、城市、暴雨、巨浪、烟花、火箭、火山……）都是 **MiniMax H3** 生成的。它同时出画面和环境声。

## 两种用法

| | 官方 API（档位 ②） | 本地显卡（档位 ③） |
|---|---|---|
| 画质 | 原生 2K（2560×1440），细节真实得多 | 16 GB 显存要用压缩权重 + 8 步加速，1344×768 |
| 速度 | 6 秒一条约 4 分钟，可以同时提交多条 | 5 秒一条约 4.5 分钟，一次只能跑一条 |
| 成本 | 2K ¥0.8/秒，768P ¥0.5/秒 | 电费 |
| 麻烦程度 | 注册、充值、填 Key 就行 | 装 ComfyUI、下几十 GB 权重、调虚拟内存，可能崩 |
| 能做的事 | 文生、首尾帧、参考图 / 视频 / 音频 | 同左 |

**新手直接用 API。** 《溢出》全片 11 条 2K 镜头约 ¥58。

## 让 AI 出片的说法

```
这个镜头要：夜里的城市上空，巨型烟花同时炸开，一浪比一浪大，最后满天亮如白昼。12 秒，2K。
先出一条给我看，满意再说。
```

AI 会：
1. 写提示词；
2. 报价（12 秒 × ¥0.8 = ¥9.6）；
3. 等你同意后提交，出来后给你看拼图。

## 提示词写法（官方三段式）

```
integrated_multimodal_description: [Shot 1] Live-action, cinematic, a single continuous 〈景别、机位〉 of 〈主体〉. 〈按时间顺序：先…… 然后…… 最后……〉. The camera 〈运动 / 保持静止〉.

overall_soundscape: 〈环境声，和画面事件对应〉

non_diegetic_music: N/A
```

- **只写一个连续镜头：** 要剪辑，自己在后期剪。
- **按时间写，写出「越来越……」：** 模型会照着节奏推进，适合做高潮。
- **一个强主体，一眼能看懂：** 快剪里一个镜头只有 0.5–1 秒。
- **音乐写 N/A：** 配乐自己做，模型的音乐不好用；环境声可以留着当底。
- **画面里别要文字：** 招牌、编号都会糊。

`prompts/h3/` 里有 23 条实拍用过的提示词，照着改最快。

## 首尾帧转场：让代码画面「变成真的」

这是《溢出》最出彩的技巧：**第一帧是代码画面，最后一帧是写实镜头，中间让模型自己接上。**

1. **先出写实镜头**，例如一条巨浪。
2. **按它的第一帧摆代码画面：** 海平线在哪、浪在哪，代码画的线框海面就对到哪。
3. **导出转场起点那一帧：** 关掉 HUD、颗粒、水印的干净版本。
4. **交给模型首尾帧模式：** 首帧 = 这张代码画面，尾帧 = 写实镜头第一帧。提示词写清楚**怎么变、变多久**：
   ```
   网格的每一格亮成一扇窗，从中心往外扩散，到第 4 秒全部变成城市夜景。
   ```
   不写过程的话，模型会 0.3 秒一刷就切过去，观众看不到「变」。
5. **检查接缝：** AI 会算首帧、尾帧和前后画面的相似度（PSNR）。
   - 30 dB 左右可以直接硬切。
   - 22 dB 左右（代码里细小的数字被糊掉），用 6–12 帧交叉淡化。

**注意：** 转场做好以后，就不要再换它两头的镜头，也不要改后期、调色、字体，否则接缝会露。
AI 在最终渲染前会做一次「关键帧逐像素一致」检查。

## 挑镜头：贵的不一定更好

- 每条都看拼图（6–9 帧），对照这个镜头要打响的那一拍来判断。
- **升级 2K 时逐条对比，别整批替换：** 《溢出》升级时，闪电劈地、火山喷发这两条本地版反而更猛，就留了本地版。
- **不行就重抽：** 换个种子、改提示词。一条几分钟、几块钱，不要为一条差镜头将就。

## 本地跑（档位 ③）要点

- **启动：** 服务由**你自己**双击启动，开在自己的窗口里。AI 在后台启动的话，内存一紧张会被系统收掉。
- **一次只跑一条：** 只让一个分身往队列里提交任务（`scripts/run_queue.py`）。服务挂了，队列会等你重启，不会重复提交。
- **虚拟内存必须调大：** 约要 35 GB 提交内存，见 `01_电脑和网络.md`。
- **自定义节点能少开就少开：** 有的节点会因为缺 DLL 弹错误框、卡住启动。
- **高级玩法：**
  - 参考图固定人物：`<Picture N>`。
  - Blender 参考视频控制机位：`<Video N>`。
  - 配音音频 + `fully_copy` 对口型：`<Audio N>`。
